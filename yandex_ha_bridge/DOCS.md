# Yandex HA Bridge — документация

## Назначение

Аддон подключается к официальному API Яндекс Умного дома и предоставляет Home Assistant доступ к выбранным пользователем устройствам.

Устройства при этом остаются подключёнными к Яндексу. Alice продолжает работать без изменений.

## Текущая версия: 0.2.0

Версия **0.2.0** добавляет выбор устройств через встроенный веб-интерфейс.

Аддон:

1. подключается к API Яндекса;
2. проверяет OAuth-токен;
3. получает список доступных устройств;
4. показывает устройства в веб-интерфейсе;
5. сохраняет только выбранные пользователем `device_id`;
6. обрабатывает в цикле только выбранные устройства.

Управление устройствами и создание сущностей Home Assistant пока не выполняются.

## Выбор устройств

После запуска откройте **Настройки → Дополнения → Yandex HA Bridge → Открыть веб-интерфейс** либо пункт **Yandex HA Bridge** в боковом меню, если он отображается.

В интерфейсе будет показан список устройств Яндекс Умного дома. Для каждого устройства отображаются:

- имя;
- модель;
- тип;
- `device_id`.

Отметьте нужные устройства и нажмите **«Сохранить выбор»**.

Выбранные идентификаторы сохраняются локально в:

`/data/selected_devices.json`

Поэтому выбор не теряется при перезапуске аддона.

Важно: получение полного списка устройств из API необходимо только для отображения выбора. Сам bridge не публикует и не обрабатывает в дальнейшем не выбранные устройства.

## OAuth-токен

Для чтения устройств нужен OAuth-токен с разрешением `iot:view`.

Официальный API Яндекса использует адрес:

`https://api.iot.yandex.net`

Для получения списка устройств используется:

`GET /v1.0/user/info`

Для получения состояния конкретного устройства используется:

`GET /v1.0/devices/{device_id}`

Токен передаётся в HTTP-заголовке:

`Authorization: Bearer YOUR_OAUTH_TOKEN`

Для тестирования Яндекс также предоставляет отладочный OAuth-токен.

## Настройка аддона

Откройте **Настройки → Дополнения → Yandex HA Bridge → Конфигурация**.

### `yandex_oauth_token`

OAuth-токен Яндекса.

Токен хранится в локальной конфигурации Home Assistant и не должен публиковаться в GitHub.

### `device_id`

Старый параметр для ручной диагностики конкретного устройства. В версии 0.2.0 основной способ выбора — встроенный веб-интерфейс. Для нового сценария оставляйте поле пустым.

### `poll_interval`

Интервал между запросами к API в секундах.

По умолчанию: `30` секунд.

Минимальное значение: `10` секунд.

### `log_level`

Уровень логирования:

- `debug` — подробная диагностика;
- `info` — обычный режим;
- `warning` — только предупреждения и ошибки;
- `error` — только ошибки.

## Проверка работы

После запуска в журнале должны появиться сообщения примерно такого вида:

```text
Yandex HA Bridge v0.2.0 запускается
Веб-интерфейс выбора устройств запущен на порту 8099
Соединение с API Яндекс Умного дома установлено
Устройства ещё не выбраны. Откройте веб-интерфейс аддона и выберите нужные устройства.
```

После выбора:

```text
Выбрано устройств: 2 из 12 доступных
Выбрано: id=..., имя=..., модель=...
```

## Безопасность

Никогда не публикуйте OAuth-токен:

- в GitHub;
- в README;
- в CHANGELOG;
- в Dockerfile;
- в исходном коде;
- в скриншотах логов.

## Версионность

Полная история релизов хранится в `CHANGELOG.md`.

Home Assistant определяет наличие обновления по версии из `config.yaml`.

Правила проекта:

- `0.1.x` — чтение и диагностика;
- `0.2.x` — выбор устройств;
- `0.3.x` — сущности Home Assistant;
- `0.4.x` — управление устройствами;
- `0.5.x` — синхронизация состояния;
- `0.6.x+` — расширение поддержки устройств.

## План развития

### 0.3.0

Добавить автоматическое создание сущностей в Home Assistant через MQTT Discovery **только для выбранных устройств**.

### 0.4.0

Добавить управление светом через `POST /v1.0/devices/actions` с правом `iot:control`.

### 0.5.0

Добавить двустороннюю синхронизацию состояния и обновление состояния после команд.

### Далее

Добавить поддержку нескольких типов устройств и автоматическое восстановление после временной потери соединения.

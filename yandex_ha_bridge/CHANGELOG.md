# История изменений

## 0.3.10 — 8 сентября 2026

### Device Registry / Home Assistant 2026.8+
- Исправлена передача исходного `ConfigEntry` в `DataUpdateCoordinator` через `config_entry=entry`.
- Это устраняет сценарий, при котором `light` entity имеет `unique_id` и `device_info`, но Home Assistant отбрасывает связь entity с Device Registry из-за отсутствующего `config_entry_id`.
- Сохранена автоматическая регистрация устройства через `_attr_device_info`.
- Убрана необходимость ручной регистрации устройства.

### Actions
- Ошибка выполнения одного action больше не переводит весь `DataUpdateCoordinator` в `UpdateFailed`.
- Пустой список actions не отправляется в Yandex API.
- Для `POST /v1.0/devices/actions` сохранена явная диагностика `HTTP 403` и требования OAuth `iot:control`.
- JSON payload для action сериализуется компактно и предсказуемо.

### Версии
- Синхронизированы `manifest.json`, `const.py`, App `config.yaml`, API и App User-Agent: `0.3.10`.
- Обновлён README с инструкцией тестирования после обновления.

## 0.3.9 — 8 сентября 2026

### Device Registry
- Исправлена привязка `light` entity к устройству Home Assistant.
- Убрана ручная предварительная регистрация устройств из `async_setup_entry`.
- `DeviceInfo` теперь задаётся непосредственно в конструкторе `YandexLight` через `_attr_device_info`.
- Используется один и тот же уникальный идентификатор `(yandex_ha_bridge, Yandex device ID)` для регистрации устройства и entity.
- Это устраняет ситуацию, когда страница устройства существует, но показывает «У этого устройства нет объектов».

### Совместимость с Home Assistant 2026.8+
- Регистрация устройства приведена к актуальному рекомендуемому Home Assistant подходу: устройство создаётся автоматически из `device_info` сущности, загруженной через Config Entry.
- Убрана дублирующая ручная работа с Device Registry.

### Версии
- Синхронизированы версии `manifest.json`, `const.py`, App и API User-Agent: `0.3.9`.

## 0.3.8 — 8 сентября 2026

### Device Registry Home Assistant
- Исправлена регистрация выбранных Yandex-устройств в Device Registry Home Assistant.
- Каждая выбранная лампа теперь создаётся как отдельное физическое устройство, а не как entity без устройства.
- Для light entity используется явный `DeviceInfo` с уникальным идентификатором Yandex device ID.
- При загрузке Config Entry устройство также явно создаётся/обновляется через Device Registry.
- Для устройства сохраняются имя, производитель, модель и serial/device ID, если они доступны.

### Интерфейс и описание
- Обновлено описание App.
- Обновлены тексты Config Flow и Options Flow на русском и английском языках.
- Веб-панель обозначена как диагностическая; основное добавление устройств выполняется через интеграцию Home Assistant.

### Версии
- Синхронизированы версии `manifest.json`, `const.py`, App и API User-Agent: `0.3.8`.

## 0.3.7 — 8 сентября 2026

### Управление светом и совместимость
- Исправлено использование актуального Home Assistant Light API.
- Добавлены `ATTR_RGB_COLOR` и `ATTR_COLOR_TEMP_KELVIN` из `homeassistant.components.light`.
- Команды управления формируются только для реально доступных capabilities устройства.
- Платформа добавляет только устройства типа `devices.types.light`.
- Усилена типизация и структура `light.py`.

### CI и версии
- Версия автоматически сверяется между `manifest.json`, App `config.yaml`, `bridge.py`, README и CHANGELOG.
- Workflow больше не содержит жёстко заданный номер релиза.
- Добавлены проверки актуальных Home Assistant Light API imports.

### OAuth
- Сохранено явное объяснение требования `iot:control` для `POST /v1.0/devices/actions`.
- `HTTP 403` рассматривается как отсутствие права управления у OAuth-токена, если Яндекс отклоняет action-запрос.

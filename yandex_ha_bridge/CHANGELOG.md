# Changelog

## 0.5.1 — 2026-09-09

### Исправлено
- Пресет `Тёплый белый` в `Режим` больше не отправляет произвольный HSV-цвет.
- `Тёплый белый` теперь использует `temperature_k` и автоматически выбирает минимальную поддерживаемую цветовую температуру конкретной лампы — то есть самый тёплый белый.
- Текущий режим `temperature_k` корректно отображается как `Тёплый белый`.

### Важно про «Добавить на панель»
- Поведение кнопки `Добавить на панель` не управляется custom integration. Это функция frontend Home Assistant.
- В Home Assistant 2026.7+ известна проблема, при которой после `Добавить на панель` интерфейс показывает успешное сохранение, но карточка фактически не появляется. Это не ошибка Yandex HA Bridge.
- Рабочий обходной путь: открыть нужную панель → `Изменить панель` → `Добавить карточку` → выбрать устройство/сущность Yandex.

## 0.5.0 — 2026-09-09

### Новое
- Сцены Yandex теперь также представлены непосредственно на `light` entity как нативные Home Assistant effects.
- Добавлен `effect_list` с реальными сценами устройства и обработка `light.turn_on` с `effect`.
- `Режим` теперь содержит только цветовые пресеты и реальные Yandex-сцены; температурные пресеты из него удалены.
- Для Device Registry у `Режим` теперь также используется область устройства, если её сообщает Yandex.

### Изменено
- `actions.py` дополнительно нормализует и ограничивает RGB-каналы до 0–255.
- Все action payloads по-прежнему строятся централизованно, поэтому `light` и `Режим` не могут разойтись по формату Yandex API.
- Для сцен action instance остаётся строго `scene`; `color_scene` используется только как capability parameter.

### Важно про «Избранное» Home Assistant
- Нативное Home Assistant «Избранное» для света предназначено для сохранённых цветов и цветовой температуры и не предоставляет integration API для добавления туда произвольных Yandex-сцен.
- Поэтому Yandex-сцены добавлены как нативные `light effects`: их можно использовать через стандартную карточку света с функцией `light-effect`.
- Температурные пресеты из отдельного `Режим` убраны, поскольку цветовая температура уже управляется штатным контролом Light entity.

### Исправлено
- Убрана путаница, когда температурные пресеты выглядели как режимы цвета.
- Усилена защита action payloads от дробных и выходящих за диапазон числовых значений.

### Известное ограничение
- Точное содержимое пользовательских цветовых «Избранных» Home Assistant хранится на стороне frontend и не передаётся custom integration. Поэтому интеграция не может программно узнать, какой именно цвет пользователь сохранил под «избранным №2», и безопасно подменить им Yandex-пресет без данных из frontend.

## 0.4.1 — 2026-09-09

### Исправлено
- Полностью централизовано построение команд управления Yandex API в отдельном модуле `actions.py`.
- Исправлен формат HSV-команд: Yandex API требует целые значения `h`, `s`, `v`; теперь все три поля всегда отправляются как `int` в допустимых диапазонах.
- Исправлен формат команд цветовых сцен: имя capability-параметра `color_scene` не используется как action instance; для команды используется `instance: scene`.
- Исправлен формат RGB-команд: RGB отправляется только устройствам, которые явно рекламируют `rgb`.
- Для пресетов цветовой температуры учитывается фактический диапазон `temperature_k.min/max` конкретной лампы.
- `Режим` корректно использует те же action builders, что и `light`, и распознаёт текущую сцену из `instance: scene`.
- Пресеты и сцены больше не отправляют неподдерживаемые режимы устройству.
- CI отдельно проверяет отсутствие ошибочного `instance: color_scene` и наличие централизованного action builder.

### Известное ограничение
- Если физический выключатель обесточивает лампу, а Yandex API продолжает возвращать `on=true`, интеграция не может достоверно определить физическое состояние только через облачный API.

## 0.4.0 — 2026-09-09

### Новое
- Добавлена отдельная `select` entity **Режим** для каждой цветной лампы.
- Добавлены быстрые пресеты и сцены, которые Яндекс рекламирует через `color_scene`.

### Исправлено
- Исправлен разбор Yandex `color_model` и диапазона `temperature_k.min/max`.
- Добавлены диагностические атрибуты состояния.

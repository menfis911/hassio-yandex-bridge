# Changelog

## 0.4.0 — 2026-09-09

### Новое
- Добавлена отдельная `select` entity **Режим** для каждой цветной лампы.
- Добавлены быстрые пресеты: **Тёплый свет**, **Нейтральный свет**, **Холодный свет**, **Красный**, **Зелёный**, **Синий**.
- Добавлены сцены, которые Яндекс реально рекламирует через `color_scene`: Чудо, Сказочные огни, Северное сияние, Рождество, Алиса, Вечеринка, Джунгли, Неон, Ночь, Океан, Романтика, Свеча, Сирена, Тревога, Фантазия, Чтение.
- Для сцен используется исходный Yandex scene ID, а для отображения — русское название.
- Пресеты цвета сохраняют текущую яркость лампы.
- Выбор пресета или сцены одновременно включает лампу.

### Исправлено
- Исправлен разбор Yandex `color_model`, когда API возвращает строку `"hsv"`, а не список.
- Исправлен разбор диапазона `temperature_k.min/max` из фактической структуры Yandex API.
- Добавлены понятные атрибуты состояния: Online, Power, Brightness, Color, Temperature, Mode.
- `available` теперь отражает `state=online`, который возвращает Yandex API.
- Диапазоны яркости и цветовой температуры теперь берутся из фактических вложенных объектов API.

### Важно
- HSV-лампа остаётся Home Assistant `HS`; RGB capability не добавляется искусственно.
- Состояние после физического выключателя продолжает зависеть от того, какое состояние возвращает Yandex API. Если API продолжает возвращать `on=true` после физического обесточивания, интеграция не может достоверно определить это только через облачный API.

## 0.3.12 — 2026-09-09

### Исправлено
- Исправлено представление Yandex `hsv` как Home Assistant `HS`, вместо ошибочного `RGB`.
- Добавлено свойство `hs_color` для корректного отображения и управления HSV-лампами в стандартной Light Card.
- Сохранена поддержка `COLOR_TEMP` для ламп, которые одновременно поддерживают HSV и цветовую температуру.
- Для `brightness` при вызове `light.turn_on` интеграция отправляет `on=true` вместе с яркостью. Это учитывает поведение Yandex API, при котором отдельный brightness action для выключенной лампы отклоняется.
- RGB action теперь отправляется только устройствам, которые явно рекламируют `rgb`.

### Информация об устройстве
- Добавлены диагностические атрибуты Light entity: Yandex device ID, тип, состояние, комната, группа, производитель, модель, цветовая модель и диапазоны яркости/цветовой температуры.
- Комната используется как `suggested_area` при регистрации Device Registry, если она доступна в данных Яндекса.

### Branding
- Добавлены собственные brand images для `Yandex HA Bridge`.

### Причина релиза
Реальная проверка API на лампе `YNDX-00019` показала, что устройство поддерживает HSV и `temperature_k`, но не поддерживает RGB. Также Yandex API отклоняет отдельный brightness action для выключенной лампы, поэтому интеграция должна включать лампу вместе с изменением яркости.

## 0.3.11 — 2026-09-08

### Исправлено
- Исправлена ошибка Home Assistant `Invalid supported_color_modes`.
- Убрана недопустимая комбинация `ColorMode.BRIGHTNESS + COLOR_TEMP`.
- Для диммируемых ламп без цвета используется `ColorMode.BRIGHTNESS`.
- Для ламп с регулировкой цветовой температуры используется `ColorMode.COLOR_TEMP`, который уже включает поддержку яркости.
- Для RGB-ламп используется `ColorMode.RGB`; при наличии цветовой температуры дополнительно используется `ColorMode.COLOR_TEMP`.
- `color_mode` теперь всегда соответствует одному из значений `supported_color_modes`.
- Исправлено падение `light` entity на этапе регистрации, из-за которого Home Assistant показывал устройство с `0 объектов`.

## 0.3.10 — 2026-09-08

### Исправлено
- `DataUpdateCoordinator` получает исходный `ConfigEntry` через `config_entry=entry`.
- Исправлена передача контекста Config Entry для Device Registry Home Assistant 2026.8+.
- Action-ошибки больше не переводят coordinator в `UpdateFailed`.
- Пустые action-запросы не отправляются.
- Улучшена диагностика HTTP 403 и требования `iot:control`.

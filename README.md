# Yandex HA Bridge

Кастомная интеграция для Home Assistant, которая получает устройства Яндекса через официальный API и добавляет выбранные устройства непосредственно в Home Assistant.

## Текущая версия

**0.6.0 — группа выбранных ламп Яндекса**

Интеграция работает через Config Flow: OAuth-токен → список устройств → выбор устройств → Config Entry.

Каждое выбранное физическое устройство Яндекса регистрируется в Home Assistant как отдельный **Device**.

Если выбрано две или больше ламп, дополнительно создаётся одна отдельная light entity **«Лампы Яндекса»**, которая управляет всеми выбранными Yandex-лампами одновременно.

## Что нового в 0.6.0

- Добавлена агрегированная light entity **«Лампы Яндекса»**.
- В группу автоматически входят все выбранные через Yandex HA Bridge устройства типа `devices.types.light`.
- Отдельные лампы не изменены и продолжают работать как раньше.
- Группа использует стандартные Home Assistant `light.turn_on` / `light.turn_off`, поэтому команды к группе проходят через существующую логику каждой отдельной лампы.
- Поддерживаются общие для всех участников возможности: включение/выключение, яркость, цветовые режимы и Yandex-сцены, если они доступны всем лампам группы.
- Группа имеет стабильный unique ID и отдельный entity ID, поэтому её можно использовать в Dashboard, автоматизациях и голосовом управлении.

## Что нового в 0.5.1

- Пресет `Тёплый белый` в `Режим` теперь использует `temperature_k`, а не произвольный HSV.
- Для конкретной лампы автоматически выбирается минимальная поддерживаемая цветовая температура — самый тёплый белый.
- При состоянии `temperature_k` режим корректно отображается как `Тёплый белый`.
- Исправлено описание версии и обновлены changelog/проверки CI.

## Возможности

- OAuth-токен Яндекса.
- Права `iot:view` и `iot:control`.
- Получение устройств через официальный Yandex Smart Home API.
- Выбор устройств при установке и через Options Flow.
- Отдельный Device Registry для каждого выбранного устройства.
- Автоматическая группа выбранных Yandex-ламп.
- Включение/выключение света.
- Яркость 0–100% с преобразованием в Home Assistant 0–255.
- HSV → Home Assistant HS.
- RGB только для устройств, которые явно рекламируют `rgb`.
- Цветовая температура.
- Цветовые пресеты.
- Yandex-сцены через capability `color_scene` и action `scene`.
- Yandex-сцены как native Home Assistant light effects.
- Диагностические атрибуты.
- Периодическое обновление состояния.

## Группа «Лампы Яндекса»

Группа создаётся автоматически, если через Config Flow выбрано минимум две Yandex-лампы.

Например, если выбраны 8 ламп:

```text
8 отдельных light entity
        ↓
light.yandex_lights
«Лампы Яндекса»
```

Группа не заменяет отдельные лампы. Они остаются доступными для точечного управления.

На Dashboard достаточно добавить одну `light` entity **«Лампы Яндекса»**. Для автоматизаций и голосовых команд можно обращаться непосредственно к этой entity.

Если часть ламп поддерживает возможности, которых нет у остальных, группа показывает только общие возможности. Это предотвращает отправку неподдерживаемых цветовых или эффект-команд отдельным лампам.

## Режимы

Для цветных ламп создаётся дополнительная `select` entity **Режим**.

Быстрые режимы:

- **Тёплый белый** — выбирает минимальную `temperature_k` конкретной лампы.
- Красный.
- Зелёный.
- Синий.

Дополнительно автоматически добавляются реальные сцены из `color_scene`, которые сообщает конкретная лампа.

Одновременно Yandex-сцены доступны как `effect` / `effect_list` у самой `light` entity.

## Home Assistant «Избранное»

Нативная функция **Light color favorites** Home Assistant предназначена для сохранённых цветов и цветовой температуры. Произвольные Yandex-сцены нельзя программно добавить в этот frontend-список через API custom integration.

Поэтому сцены представлены как нативные **light effects**. В Dashboard для них можно добавить стандартную функцию `light-effect`.

Пример карточки:

```yaml
type: tile
entity: light.yandex_lights
features:
  - type: light-brightness
  - type: light-color-temp
  - type: light-color-favorites
  - type: light-effect
```

## «Добавить на панель»

Кнопка **Добавить на панель** относится к frontend Home Assistant, а не к интеграции. В Home Assistant 2026.7 известна проблема, при которой UI сообщает об успешном сохранении, но карточка фактически не появляется.

Если это происходит, добавьте карточку вручную: **Панель → Изменить панель → Добавить карточку → Tile → выбрать `Лампы Яндекса`**.

Это не требует удаления или повторного выбора существующих Yandex-устройств.

## Состояние устройства

Light entity содержит диагностические атрибуты: `yandex_online`, `yandex_power`, `yandex_brightness`, `yandex_color`, `yandex_temperature`, `yandex_mode`, `yandex_effect`, `yandex_effects`, Yandex ID, тип, состояние, комнату, группу, производителя, модель, цветовую модель и диапазоны яркости/цветовой температуры.

Группа дополнительно показывает `member_count` и `member_entities`.

## Важное про физический выключатель

Интеграция использует cloud polling и по умолчанию обновляет состояние каждые 30 секунд.

Если физический выключатель обесточивает умную лампу, Home Assistant сможет показать `OFF` только если Яндекс API после этого возвращает соответствующее состояние. Если API продолжает возвращать `on=true`, интеграция не может достоверно определить обесточивание только через этот API.

## Важное про HTTP 403

`GET /v1.0/user/info` и `GET /v1.0/devices/{device_id}` используют `iot:view`, а `POST /v1.0/devices/actions` использует `iot:control`.

Токен должен иметь оба права: `iot:view` и `iot:control`.

## Установка / обновление

Репозиторий устанавливается через HACS как custom integration.

1. **Настройки → Устройства и службы**.
2. Найдите **Yandex HA Bridge**.
3. Обновите интеграцию до `0.6.0`.
4. Перезагрузите Home Assistant.
5. Проверьте существующие Devices и их `light` entities.
6. Если выбрано минимум две лампы, найдите новую entity **«Лампы Яндекса»**.

Удалять существующие Devices или Config Entry перед обновлением не требуется.

## Проверка после обновления

Для 8 выбранных Yandex-ламп ожидается:

- прежние 8 отдельных `light` entities продолжают работать;
- появляется одна дополнительная `light` entity **«Лампы Яндекса»**;
- включение группы включает все выбранные лампы;
- выключение группы выключает все выбранные лампы;
- изменение общей яркости передаётся выбранным лампам через их существующие `light` entities;
- общие цветовые возможности группы не ломают индивидуальное управление;
- Yandex-сцены остаются доступными на отдельных лампах;
- существующий `Режим` продолжает работать без изменений;
- `Тёплый белый` продолжает использовать минимальную `temperature_k` каждой лампы;
- физические лампы не переименовываются и не пересоздаются.

Если команда из стандартной Light Card не работает, проверьте **Настройки → Система → Журналы** и ищите `yandex_ha_bridge`.

## Архитектура

Основная работа выполняется custom integration `custom_components/yandex_ha_bridge`.

`actions.py` является единым слоем построения action payloads для `light` и `select`.

`groups.py` содержит только новый агрегированный Light entity. Он не меняет action payloads и не вмешивается в существующие Yandex entities.

## Версии

### 0.6.0
- Добавлена автоматическая группа **«Лампы Яндекса»** для выбранных Yandex-ламп.
